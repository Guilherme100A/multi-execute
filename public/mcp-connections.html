MCP MULTISSESSÃO · EXPLICAÇÃO VISUAL

Um servidor.
Vários Roblox.

Cada Roblox possui seu próprio cliente Lua e sua própria conexão. Todos entram pela porta 28429, e o servidor usa o worker_id para entregar cada comando ao jogo correto.

Resposta diretaCada sessão não inicia outro servidor MCP. Ela inicia um cliente MCP exclusivo conectado ao mesmo servidor central.

IDA E VOLTA

O caminho de um comando

01Você envia o prompt

No terminal de uma sessão específica.

02Proxy fixa o worker

O modelo não escolhe outro destino.

03MCP consulta o mapa

Localiza socket e PID do worker.

04Lua executa no Roblox

Somente o processo selecionado recebe.

05Resultado retorna

Mesmo socket, mesmo worker, mesmo terminal.

COMPARTILHADO

Existe apenas um

  • 01Servidor roblox-mcp-difz
  • 02Endereço 127.0.0.1
  • 03Porta TCP 28429
  • 04Registro central de sessões

EXCLUSIVO POR SESSÃO

Cada Roblox possui o seu

  • 01Processo e PID do Roblox
  • 02Cliente MCP escrito em Lua
  • 03Conexão WebSocket/stream
  • 04worker_id, terminal e histórico

POR QUE A MESMA PORTA FUNCIONA?

Porta não é conexão

127.0.0.1:50121 · Roblox A127.0.0.1:50122 · Roblox B127.0.0.1:50123 · Roblox C
DESTINO COMPARTILHADO127.0.0.1:28429

O sistema operacional identifica cada conexão pela combinação de origem e destino. Mesmo que o destino seja sempre :28429, as portas temporárias de origem e os sockets são diferentes.

ISOLAMENTO DE FALHAS

Se o Roblox B cair

O servidor remove apenas o socket e o registro da sessão B.

Roblox A continua conectado
Roblox B socket #2 removido
Roblox C continua conectado

O servidor MCP permanece na porta 28429. Os terminais A e C continuam funcionando; somente a sessão B muda para disconnected.
